# หลังบ้าน — Apps Script บนชีทของร้าน

โค้ดในโฟลเดอร์นี้ทำงานอยู่บน Google ไม่ใช่ในเครื่อง ข้อมูลทั้งหมดอยู่ในชีท
`AST_ระบบออเดอร์และสต๊อก3008` ไม่มีข้อมูลลูกค้าอยู่ในไฟล์เหล่านี้เลย

## กติกาข้อเดียวที่ห้ามลืม

ชีทของร้าน **ใส่สูตรรอไว้ทุกแถวแล้ว** ตั้งแต่แถว 6 ถึงแถว 501 (หัวบิล) และ 1201 (รายการ)
แถวที่ดูว่างเปล่าก็มีสูตรอยู่ มันแค่คืนค่าว่างเพราะยังไม่มีข้อมูลให้คำนวณ

> เขียนตัวเลขทับช่องสูตรเมื่อไร สูตรแถวนั้นหายถาวร
> ยอดสินค้า ต้นทุน กำไร VAT ของออเดอร์ใบนั้นจะค้างเป็นเลขนิ่ง ไม่อัปเดตอีกเลย และไม่มีอะไรฟ้อง

`Sheets.gs` จึงมีตาราง `SH` บอกว่าคอลัมน์ไหนกรอกได้ คอลัมน์ไหนเป็นสูตร
และ `writeRow_()` จะโยน error ทันทีถ้ามีโค้ดพยายามเขียนลงช่องสูตร

| ชีท | ช่องที่เขียนได้ | ช่องสูตร ห้ามแตะ |
|---|---|---|
| ออเดอร์_หัวบิล | A–I, K, L, Q, S, T | J, M, N, O, P, R, U |
| ออเดอร์_รายการ | B, D, G, I | A, C, E, F, H, J–P และ Q ที่เพิ่มใหม่ |

## ไฟล์

| ไฟล์ | ทำอะไร |
|---|---|
| `Sheets.gs` | รู้ว่าคอลัมน์ไหนอยู่ตรงไหน · อ่าน/เขียนแถวอย่างปลอดภัย · หาแถวว่าง |
| `Fefo.gs` | เลือกล็อตที่หมดอายุก่อนมาตัดก่อน — โค้ดล้วน ไม่แตะชีท ทดสอบด้วย node ได้ |
| `Setup.gs` | สร้างชีท `ล็อตสินค้า` · `ตัดล็อต` และเพิ่มคอลัมน์ Q ที่ `ออเดอร์_รายการ` |
| `Api.gs` | สิทธิ์เข้าใช้ · เสิร์ฟหน้าเว็บ · `createOrder()` บันทึกออเดอร์ |
| `Index.html` | หน้าจอคีย์ออเดอร์ · รับของเข้า · เสนอราคา · สรุปยอด บนมือถือ |
| `Backup.gs` | **โปรเจกต์แยก** — สำรองไฟล์ชีทลงไดรฟ์ทุกวัน เก็บ 30 วัน (ดูหัวข้อข้างล่าง) |

## ติดตั้งครั้งแรก

1. เปิดชีท → เมนู **ส่วนขยาย › Apps Script**
2. เพิ่มไฟล์ตามรายการข้างบน (ไฟล์ `.gs` เลือกชนิด **สคริปต์** · `.html` เลือก **HTML**
   ตอนตั้งชื่อไม่ต้องพิมพ์นามสกุลต่อท้าย)
3. **การตั้งค่าโปรเจกต์** → ติ๊ก "แสดงไฟล์ appsscript.json" แล้ววางเนื้อหาจาก `appsscript.json` ทับ
4. เลือกฟังก์ชัน **`setup`** กด **Run** ครั้งเดียว แล้วอนุญาตสิทธิ์ตามที่ Google ถาม
   (สั่งซ้ำได้ ไม่ทำข้อมูลหาย · จะซ่อมสูตร `#REF!` ในชีทสต๊อกให้ด้วยถ้ามี)
5. **ทำให้ใช้งานได้ › การทำให้ใช้งานได้ใหม่ › เว็บแอป**
   - ทำงานในชื่อ: **ผู้ใช้ที่เข้าถึงเว็บแอป**
   - ผู้ที่มีสิทธิ์เข้าถึง: **ทุกคนที่มีบัญชี Google**
6. ส่งลิงก์ที่ได้ให้พนักงาน — เปิดจากมือถือแล้วกด "เพิ่มลงหน้าจอโฮม" ได้เลย

## ปล่อยเวอร์ชันใหม่ (deploy) — ทุกครั้งที่แก้โค้ด

**วางไฟล์แล้วกดบันทึกยังไม่พอ** ลิงก์เว็บแอปเสิร์ฟ "เวอร์ชันที่ปล่อยไว้ล่าสุด"
ไม่ใช่โค้ดที่เพิ่งวาง ถ้าไม่ปล่อยเวอร์ชันใหม่ พนักงานก็ยังใช้ของเก่าอยู่เหมือนเดิม

1. วาง `ไฟล์1-Code-gs.txt` ทับ `Code.gs` · `ไฟล์2-Index-html.txt` ทับ `Index.html` → กด **💾 บันทึก**
2. มุมขวาบน **ทำให้ใช้งานได้** → **จัดการการทำให้ใช้งานได้**
3. กด **✏️** ที่รายการเดิม → ช่อง **เวอร์ชัน** เลือก **เวอร์ชันใหม่** → **ทำให้ใช้งานได้**

> ห้ามกด **"การทำให้ใช้งานได้ใหม่"** (New deployment) เพราะจะได้ลิงก์ใหม่คนละอัน
> คนที่ใช้ลิงก์เดิมจะค้างอยู่กับโค้ดเก่าตลอดไปโดยไม่มีอะไรฟ้อง

ปล่อยเสร็จแล้ว **ปิดแอปในมือถือแล้วเปิดลิงก์ใหม่** — หน้าที่เปิดค้างไว้ยังถือโค้ดเก่า
และคุยกับเวอร์ชันที่ถูกแทนที่ไปแล้ว จะขึ้น `HTTP 0` ตอนกดบันทึก

สั่ง `setup` ซ้ำ **ไม่ต้อง** ยกเว้นตอนที่บอกไว้ว่าต้องสั่ง (เพิ่มชีทหรือคอลัมน์ใหม่)

## ใครเข้าระบบได้

**แชร์ชีทให้ใคร คนนั้นใช้แอปได้** — ไม่ต้องตั้งอะไรเพิ่ม ไม่ต้องรู้ว่าโดเมนบริษัท
เป็น Google Workspace หรือเปล่า

> เปิดชีท → กด **แชร์** → ใส่อีเมลพนักงาน → เลือก **ผู้แก้ไข**

เหตุผลที่ผูกกับการแชร์ชีท: คนที่แก้ชีทได้ ก็ทำทุกอย่างที่แอปทำได้อยู่แล้ว
การมีรายชื่อสองที่ให้ดูแลมีแต่จะหลุด

ด่านนี้ไม่ได้อ่านรายชื่อผู้แก้ไขมาเทียบ แต่**ลองเปิดชีทในนามคนที่กดเข้ามาตรง ๆ**
เปิดได้คือผ่าน เพราะแอปทำได้แค่เท่าที่บัญชีนั้นทำกับชีทได้อยู่แล้ว และการเขียน
ยังมี Google กันอีกชั้น คนที่มีสิทธิ์แค่ดูจะบันทึกออเดอร์ไม่ผ่านอยู่ดี

> เคยทำแบบอ่านรายชื่อจาก Drive มาก่อนแล้วพัง — แอปทำงาน "ในชื่อผู้ใช้ที่เข้าถึง"
> DriveApp จึงถามในนามพนักงาน ซึ่งคนที่เป็นแค่ผู้แก้ไขมักอ่านรายชื่อผู้ร่วมงานไม่ได้
> ได้รายชื่อว่างกลับมา แล้วปฏิเสธคนที่เจ้าของแชร์ชีทให้เรียบร้อยแล้วจริง ๆ

พอเปิดผ่านแล้วระบบจำไว้ 5 นาที ส่วนคำว่า "ไม่ผ่าน" ไม่ถูกจำ — แชร์ชีทเสร็จเข้าได้ทันที
เอาคนออกก็ถอนสิทธิ์ในชีทตามปกติ (รออีกไม่เกิน 5 นาที)

ยังมีอีกสองทางสำรองที่ผ่านได้เหมือนกัน ใช้เมื่อจำเป็น:

| ทาง | ตั้งที่ไหน |
|---|---|
| อีเมลลงท้าย `@chem-inno-tech.com` | ค่า `ALLOW_DOMAIN` ใน `Api.gs` |
| รายชื่อเฉพาะราย | การตั้งค่าโปรเจกต์ › คุณสมบัติของสคริปต์ คีย์ `ALLOW_EMAILS` |

ด่านจริงอยู่ใน `requireStaff_()` ไม่ใช่ที่หน้าจอ — คนที่ไม่ผ่านทั้งสามทาง
ต่อให้รู้ลิงก์ก็เรียกฟังก์ชันไม่ได้ และถ้าระบบอ่านอีเมลไม่ออก จะปฏิเสธไว้ก่อนเสมอ

## ทดสอบก่อนแตะของจริง

```bash
node tools/t_fefo_unit.js                          # ตรรกะ FEFO
node tools/t_order_sheet.js                        # บันทึกออเดอร์บนชีทจำลอง
node tools/t_doc.js                                # เอกสารสี่ชนิดและตัวสะกดเงิน
node tools/t_backup.js                             # สำรองชีทอัตโนมัติ (Drive จำลอง)
python3 tools/make_preview.py && node tools/t_ui.js # หน้าจอจริงในเบราว์เซอร์

# สอบไฟล์ที่รวมแล้ว (ตัวที่เอาไปวางใน Apps Script จริง) ด้วยข้อสอบชุดเดียวกัน
python3 tools/bundle.py
BUNDLE=1 node tools/t_order_sheet.js
python3 tools/make_preview.py out/preview_bundle.html out/bundle/Index.html
PV=preview_bundle.html node tools/t_ui.js
```

`tools/fakesheet.js` จำลอง SpreadsheetApp มากพอที่จะรัน `Sheets.gs` กับ `Api.gs`
ได้ทั้งไฟล์ และ **จดไว้ทุกครั้งที่มีการเขียนทับช่องสูตร** — ข้อสอบที่สำคัญที่สุด
ของชุดทดสอบนี้คือรายการนั้นต้องว่างเปล่า

`tools/make_preview.py` ประกอบไฟล์ทั้งหมดเป็นหน้าเว็บไฟล์เดียวที่เปิดในเครื่องได้
พร้อม `google.script.run` จำลอง แล้ว `tools/t_ui.js` ขับด้วยเบราว์เซอร์จริง
ตั้งแต่วางข้อความจากไลน์จนพิมพ์ใบปะหน้าออกมาเป็นรูป

ข้อมูลในไฟล์ทดสอบทั้งหมดเป็นข้อมูลสมมติ **ห้ามเอาชื่อ เบอร์ หรือที่อยู่ลูกค้าจริง
มาใส่ในไฟล์ทดสอบ** — `tools/build.py` มีด่านตรวจเบอร์โทรไว้ให้แล้ว

## รับของเข้าสต๊อก (แท็บ 📥 รับของ)

การรับของต้องลงสองชีทเสมอ — `รับเข้า` (ยอดสต๊อก) กับ `ล็อตสินค้า` (ของให้ FEFO ตัด)
ขาดอันใดอันหนึ่งคือพังแบบเงียบ ๆ:

| ลงแค่ | ผลที่ได้ |
|---|---|
| ล็อตอย่างเดียว | ล็อตมีของ แต่ยอดคงเหลือเป็นศูนย์ · ช่องตรวจในชีทล็อตฟ้อง |
| รับเข้าอย่างเดียว | สต๊อกเพิ่ม แต่ขายไม่ได้ เพราะ FEFO ไม่มีล็อตให้ตัด |

`receiveStock()` จึงเขียนทั้งสองแถวในคำสั่งเดียว จำนวนมาจากตัวเลขเดียวกัน ล้มกลางทาง
ถอยกลับทั้งคู่ · `clientKey` กันกดซ้ำ · สินค้าที่มีล็อตอยู่แล้วจะ**ไม่ยอมให้รับเข้าโดยไม่ใส่เลขล็อต**
· เลขล็อตซ้ำของ SKU เดิมไม่ผ่าน · ยอดที่โชว์กลับมาอ่านจากชีทหลังคำนวณจริง ไม่ได้บวกเอาในแอป

## สูตรในชีทพัง — ซ่อมด้วย `repairOrderSheets`

ที่ Apps Script เลือกฟังก์ชัน **`repairOrderSheets`** แล้วกด **เรียกใช้** ซ่อมได้สองอาการ

| อาการ | หน้าตา |
|---|---|
| **เลขนิ่ง** | ช่องสูตรถูกพิมพ์ทับ หรือถูก "วางเฉพาะค่า" — ตัวเลขเท่ากันทุกแถว |
| **`#REF!`** | ยังเป็นสูตร แต่ชี้ไปหาช่องที่ถูกลบ — แอปจะขึ้นป้ายแดง "ช่องสูตรเสียในชีท" |

ตัวซ่อม**ไม่เดาสูตรเอง** — คัดลอกจากแถวที่สูตรยังครบในชีทเดียวกัน (สูตรพวกนี้เจ้าของร้าน
เขียนเอง เดาผิดแม้ช่องเดียวคือใบเสร็จยอดผิด) ถ้าไม่มีแถวไหนดีเลยจะบอกให้ซ่อมมือ ไม่มั่ว
และแตะเฉพาะคอลัมน์ใน `CALC` เท่านั้น ช่องที่คนกรอกเองไม่ถูกแตะ

ถ้ามีเลขนิ่งค้างอยู่**ใต้**แถวสุดท้ายที่มีสูตร จะรายงานเลขแถวให้ไปกด Delete เอง —
ไม่ลบให้เพราะแยกไม่ออกว่าตั้งใจเขียนไว้เองหรือเปล่า

### ถ้าไม่เหลือแถวดีให้เป็นต้นแบบเลย — `writeVatFormulas`

เกิดขึ้นได้เมื่อสูตร `#REF!` ถูกคัดลอกไปทับทั้งคอลัมน์ `repairOrderSheets` จะบอกว่า
"ไม่มีแถวไหนสูตรครบเลย" ตอนนั้นให้สั่ง **`writeVatFormulas`** ซึ่งเขียนสูตรสองช่องนี้
ที่ `ออเดอร์_หัวบิล` คืนให้:

```
M (VAT)          = (ยอดสินค้า − ส่วนลด) × ตั้งค่า!B8   เฉพาะใบที่ "รับ VAT" · ไม่คิดกับค่าส่ง
N (ยอดชำระสุทธิ)  = ยอดสินค้า − ส่วนลด + ค่าส่ง + VAT
```

**นี่เป็นที่เดียวในระบบที่ยอมเขียนสูตรของเจ้าของร้านเอง** พิสูจน์กับใบที่สูตรยังดีทุกใบก่อน
เกิดเหตุแล้ว (0016 · 0023 · 0026 · 0027 · 0029-0032 · 0034 · 0035) และอัตรา VAT อ่านจาก
`ตั้งค่า!B8` ซึ่งเป็นช่องเดียวกับที่ `cfgGet_()` ใช้ ไม่ฝัง 7% ไว้ในสูตร

ถ้าสูตรยังดีอยู่มันจะไม่ยอมเขียนทับ ต้องยืนยันด้วย `writeVatFormulas('เขียนทับ')` ·
แตะแค่สองคอลัมน์นี้ ในช่วงแถวที่มีสูตรอยู่แล้ว · ลงบันทึกในชีท `Log` ทุกครั้ง

> **7 ก.ย. 69** ช่อง VAT กับยอดสุทธิของใบที่ "รับ VAT" เป็น `#REF!` ทั้งคอลัมน์
> ตัวซ่อมรุ่นเดิมดูแค่ว่าขึ้นต้นด้วย `=` ไหม เลยนับว่าปกติและไม่ซ่อมให้

## สำรองไฟล์ชีทอัตโนมัติ (`Backup.gs`)

6 ก.ย. 69 ไฟล์ชีทถูกลบโดยไม่ตั้งใจ กู้จากถังขยะไม่ทัน รอดมาได้เพราะบังเอิญมีแท็บ
ที่เปิดค้างไว้ให้ก๊อปข้อมูลออกมา — ครั้งหน้าอาจไม่มีแท็บนั้น

**ต้องวางใน Apps Script โปรเจกต์ใหม่ ไม่ใช่โปรเจกต์ของแอปคีย์ออเดอร์** เพราะการก๊อป
ไฟล์ต้องขอสิทธิ์เข้าถึง Google Drive ถ้าใส่รวมไปในแอป พนักงานทุกคนที่เปิดแอปจะโดน
ถามสิทธิ์ Drive ตามไปด้วยทั้งที่ไม่ได้ใช้ ให้เจ้าของร้านคนเดียวอนุญาตในโปรเจกต์นี้พอ

1. https://script.google.com → **โปรเจกต์ใหม่** ตั้งชื่อ `AST สำรองชีทอัตโนมัติ`
2. วาง `Backup.gs` ทั้งไฟล์ทับโค้ดตัวอย่าง → 💾 บันทึก
3. เลือกฟังก์ชัน `setupBackup` → **เรียกใช้** → อนุญาตสิทธิ์ Drive ครั้งเดียว
4. เสร็จ — จะได้โฟลเดอร์ `AST_สำรองชีทอัตโนมัติ` พร้อมไฟล์สำรองใบแรกทันที

| ฟังก์ชัน | ทำอะไร |
|---|---|
| `setupBackup()` | ตั้งให้สำรองเองทุกวันตอนตีหนึ่ง + สำรองให้เลยหนึ่งรอบ · กดซ้ำไม่เกิดทริกเกอร์ซ้ำ |
| `backupStatus()` | สำรองล่าสุดเมื่อไร มีกี่ไฟล์ ล้มครั้งสุดท้ายเพราะอะไร |
| `backupNow()` | สำรองเดี๋ยวนี้หนึ่งรอบ |
| `stopBackup()` | เลิกสำรองอัตโนมัติ (ไฟล์ที่สำรองไว้แล้วไม่ถูกลบ) |

ของเก่ากว่า 30 วันจะถูก**ย้ายลงถังขยะ** ไม่ใช่ลบถาวร และ**เหลือไว้อย่างน้อย 7 ไฟล์เสมอ**
ต่อให้เก่าหมดทุกใบ · ไฟล์ที่ชื่อไม่ตรงรูปแบบ `AST สำรอง YYYY-MM-DD HHMM` จะไม่ถูกแตะ
ถึงจะอยู่ในโฟลเดอร์เดียวกัน · ก๊อปล้มเมื่อไร จะไม่ไปลบของเก่าทิ้ง

ย้ายไฟล์ชีทเมื่อไร ต้องมาตั้ง `SHEET_ID` ที่คุณสมบัติสคริปต์ของโปรเจกต์นี้ด้วย
ไม่งั้นจะสำรองไฟล์เก่าต่อไปเรื่อย ๆ

## สิ่งที่ระบบกันไว้ให้แล้ว

- คนสองคนกดพร้อมกัน → `LockService` กันเลขออเดอร์ซ้ำ
- กดซ้ำ / เน็ตหลุดแล้วยิงใหม่ → `clientKey` ทำให้ได้ออเดอร์ใบเดิม ไม่ใช่ใบใหม่
- บันทึกล้มกลางทาง → ล้างแถวที่เพิ่งเขียนออกหมด ไม่ทิ้งออเดอร์ครึ่งใบ (และไม่ล้างสูตรทิ้ง)
- ยอดที่ชีทคำนวณไม่ตรงกับที่ควรเป็น → ยกเลิกทั้งใบ ดีกว่าปล่อยยอดผิดค้างไว้
- ชีทเต็ม (สูตรลากมาไม่ถึง) → บอกตรง ๆ ว่าเต็มและสูตรมีถึงแถวไหน
- ล็อตไม่พอ / ล็อตหมดอายุ → ไม่ตัดขาย บอกตัวเลขจริงว่าเหลือเท่าไร
