# หลังบ้าน — Apps Script บนชีทของร้าน

โค้ดในโฟลเดอร์นี้ทำงานอยู่บน Google ไม่ใช่ในเครื่อง ข้อมูลทั้งหมดอยู่ในชีท
`AST_ระบบออเดอร์และสต๊อก3008` ไม่มีข้อมูลลูกค้าอยู่ในไฟล์เหล่านี้เลย

## กติกาข้อเดียวที่ห้ามลืม

ชีทของร้าน **ใส่สูตรรอไว้ทุกแถวแล้ว** ตั้งแต่แถว 6 ถึงแถว 501 (หัวบิล) และ 1201 (รายการ)
แถวที่ดูว่างเปล่าก็มีสูตรอยู่ มันแค่คืนค่าว่างเพราะยังไม่มีข้อมูลให้คำนวณ

> เขียนตัวเลขทับช่องสูตรเมื่อไร สูตรแถวนั้นหายถาวร
> ยอดสินค้า ต้นทุน กำไร VAT ของออเดอร์ใบนั้นจะค้างเป็นเลขนิ่ง ไม่อัปเดตอีกเลย และไม่มีอะไรฟ้อง

`Sheets.gs` จึงมีตาราง `SH` บอกว่าคอลัมน์ไหนกรอกได้ คอลัมน์ไหนเป็นสูตร
และ `writeRow_()` จะโยน error ทันทีถ้ามีโค้ดพยายามเขียนลงช่องสูตร

| ชีท | ช่องที่เขียนได้ | ช่องสูตร ห้ามแตะ |
|---|---|---|
| ออเดอร์_หัวบิล | A–I, K, L, Q, S, T | J, M, N, O, P, R, U |
| ออเดอร์_รายการ | B, D, G, I | A, C, E, F, H, J–P และ Q ที่เพิ่มใหม่ |

## ไฟล์

| ไฟล์ | ทำอะไร |
|---|---|
| `Sheets.gs` | รู้ว่าคอลัมน์ไหนอยู่ตรงไหน · อ่าน/เขียนแถวอย่างปลอดภัย · หาแถวว่าง |
| `Fefo.gs` | เลือกล็อตที่หมดอายุก่อนมาตัดก่อน — โค้ดล้วน ไม่แตะชีท ทดสอบด้วย node ได้ |
| `Setup.gs` | สร้างชีท `ล็อตสินค้า` · `ตัดล็อต` และเพิ่มคอลัมน์ Q ที่ `ออเดอร์_รายการ` |
| `Api.gs` | สิทธิ์เข้าใช้ · เสิร์ฟหน้าเว็บ · `createOrder()` บันทึกออเดอร์ |
| `Index.html` | หน้าจอคีย์ออเดอร์ · รับของเข้า · เสนอราคา · ปิดยอดวัน · สรุปยอด บนมือถือ |
| `Shopee.html` | อ่านไฟล์ที่ส่งออกจาก Shopee แล้วนำเข้าเป็นออเดอร์ (ดูหัวข้อข้างล่าง) |
| `Acct.gs` · `Acct.html` | สถานะบัญชี + ส่งเอกสารเข้าโฟลเดอร์ไดรฟ์ของบัญชี |
| `Backup.gs` | **โปรเจกต์แยก** — สำรองไฟล์ชีทลงไดรฟ์ทุกวัน เก็บ 30 วัน (ดูหัวข้อข้างล่าง) |

## ติดตั้งครั้งแรก

1. เปิดชีท → เมนู **ส่วนขยาย › Apps Script**
2. เพิ่มไฟล์ตามรายการข้างบน (ไฟล์ `.gs` เลือกชนิด **สคริปต์** · `.html` เลือก **HTML**
   ตอนตั้งชื่อไม่ต้องพิมพ์นามสกุลต่อท้าย)
3. **การตั้งค่าโปรเจกต์** → ติ๊ก "แสดงไฟล์ appsscript.json" แล้ววางเนื้อหาจาก `appsscript.json` ทับ
4. เลือกฟังก์ชัน **`setup`** กด **Run** ครั้งเดียว แล้วอนุญาตสิทธิ์ตามที่ Google ถาม
   (สั่งซ้ำได้ ไม่ทำข้อมูลหาย · จะซ่อมสูตร `#REF!` ในชีทสต๊อกให้ด้วยถ้ามี)
5. **ทำให้ใช้งานได้ › การทำให้ใช้งานได้ใหม่ › เว็บแอป**
   - ทำงานในชื่อ: **ผู้ใช้ที่เข้าถึงเว็บแอป**
   - ผู้ที่มีสิทธิ์เข้าถึง: **ทุกคนที่มีบัญชี Google**
6. ส่งลิงก์ที่ได้ให้พนักงาน — เปิดจากมือถือแล้วกด "เพิ่มลงหน้าจอโฮม" ได้เลย

## ปล่อยเวอร์ชันใหม่ (deploy) — ทุกครั้งที่แก้โค้ด

**วางไฟล์แล้วกดบันทึกยังไม่พอ** ลิงก์เว็บแอปเสิร์ฟ "เวอร์ชันที่ปล่อยไว้ล่าสุด"
ไม่ใช่โค้ดที่เพิ่งวาง ถ้าไม่ปล่อยเวอร์ชันใหม่ พนักงานก็ยังใช้ของเก่าอยู่เหมือนเดิม

1. วาง `ไฟล์1-Code-gs.txt` ทับ `Code.gs` · `ไฟล์2-Index-html.txt` ทับ `Index.html` → กด **💾 บันทึก**
2. มุมขวาบน **ทำให้ใช้งานได้** → **จัดการการทำให้ใช้งานได้**
3. กด **✏️** ที่รายการเดิม → ช่อง **เวอร์ชัน** เลือก **เวอร์ชันใหม่** → **ทำให้ใช้งานได้**

> ห้ามกด **"การทำให้ใช้งานได้ใหม่"** (New deployment) เพราะจะได้ลิงก์ใหม่คนละอัน
> คนที่ใช้ลิงก์เดิมจะค้างอยู่กับโค้ดเก่าตลอดไปโดยไม่มีอะไรฟ้อง

ปล่อยเสร็จแล้ว **ปิดแอปในมือถือแล้วเปิดลิงก์ใหม่** — หน้าที่เปิดค้างไว้ยังถือโค้ดเก่า
และคุยกับเวอร์ชันที่ถูกแทนที่ไปแล้ว จะขึ้น `HTTP 0` ตอนกดบันทึก

สั่ง `setup` ซ้ำ **ไม่ต้อง** ยกเว้นตอนที่บอกไว้ว่าต้องสั่ง (เพิ่มชีทหรือคอลัมน์ใหม่)

## ใครเข้าระบบได้

**แชร์ชีทให้ใคร คนนั้นใช้แอปได้** — ไม่ต้องตั้งอะไรเพิ่ม ไม่ต้องรู้ว่าโดเมนบริษัท
เป็น Google Workspace หรือเปล่า

> เปิดชีท → กด **แชร์** → ใส่อีเมลพนักงาน → เลือก **ผู้แก้ไข**

เหตุผลที่ผูกกับการแชร์ชีท: คนที่แก้ชีทได้ ก็ทำทุกอย่างที่แอปทำได้อยู่แล้ว
การมีรายชื่อสองที่ให้ดูแลมีแต่จะหลุด

ด่านนี้ไม่ได้อ่านรายชื่อผู้แก้ไขมาเทียบ แต่**ลองเปิดชีทในนามคนที่กดเข้ามาตรง ๆ**
เปิดได้คือผ่าน เพราะแอปทำได้แค่เท่าที่บัญชีนั้นทำกับชีทได้อยู่แล้ว และการเขียน
ยังมี Google กันอีกชั้น คนที่มีสิทธิ์แค่ดูจะบันทึกออเดอร์ไม่ผ่านอยู่ดี

> เคยทำแบบอ่านรายชื่อจาก Drive มาก่อนแล้วพัง — แอปทำงาน "ในชื่อผู้ใช้ที่เข้าถึง"
> DriveApp จึงถามในนามพนักงาน ซึ่งคนที่เป็นแค่ผู้แก้ไขมักอ่านรายชื่อผู้ร่วมงานไม่ได้
> ได้รายชื่อว่างกลับมา แล้วปฏิเสธคนที่เจ้าของแชร์ชีทให้เรียบร้อยแล้วจริง ๆ

พอเปิดผ่านแล้วระบบจำไว้ 5 นาที ส่วนคำว่า "ไม่ผ่าน" ไม่ถูกจำ — แชร์ชีทเสร็จเข้าได้ทันที
เอาคนออกก็ถอนสิทธิ์ในชีทตามปกติ (รออีกไม่เกิน 5 นาที)

ยังมีอีกสองทางสำรองที่ผ่านได้เหมือนกัน ใช้เมื่อจำเป็น:

| ทาง | ตั้งที่ไหน |
|---|---|
| อีเมลลงท้าย `@chem-inno-tech.com` | ค่า `ALLOW_DOMAIN` ใน `Api.gs` |
| รายชื่อเฉพาะราย | การตั้งค่าโปรเจกต์ › คุณสมบัติของสคริปต์ คีย์ `ALLOW_EMAILS` |

ด่านจริงอยู่ใน `requireStaff_()` ไม่ใช่ที่หน้าจอ — คนที่ไม่ผ่านทั้งสามทาง
ต่อให้รู้ลิงก์ก็เรียกฟังก์ชันไม่ได้ และถ้าระบบอ่านอีเมลไม่ออก จะปฏิเสธไว้ก่อนเสมอ

## ทดสอบก่อนแตะของจริง

```bash
node tools/t_fefo_unit.js                          # ตรรกะ FEFO
node tools/t_order_sheet.js                        # บันทึกออเดอร์บนชีทจำลอง
node tools/t_doc.js                                # เอกสารสี่ชนิดและตัวสะกดเงิน
node tools/t_backup.js                             # สำรองชีทอัตโนมัติ (Drive จำลอง)
node tools/t_shopee_unit.js                        # ตัวอ่านไฟล์ Shopee
node tools/t_acct.js                               # ส่งบัญชี (ไดรฟ์จำลอง)
python3 tools/make_preview.py && node tools/t_ui.js # หน้าจอจริงในเบราว์เซอร์

# สอบไฟล์ที่รวมแล้ว (ตัวที่เอาไปวางใน Apps Script จริง) ด้วยข้อสอบชุดเดียวกัน
python3 tools/bundle.py
BUNDLE=1 node tools/t_order_sheet.js
python3 tools/make_preview.py out/preview_bundle.html out/bundle/Index.html
PV=preview_bundle.html node tools/t_ui.js
```

`tools/fakesheet.js` จำลอง SpreadsheetApp มากพอที่จะรัน `Sheets.gs` กับ `Api.gs`
ได้ทั้งไฟล์ และ **จดไว้ทุกครั้งที่มีการเขียนทับช่องสูตร** — ข้อสอบที่สำคัญที่สุด
ของชุดทดสอบนี้คือรายการนั้นต้องว่างเปล่า

`tools/make_preview.py` ประกอบไฟล์ทั้งหมดเป็นหน้าเว็บไฟล์เดียวที่เปิดในเครื่องได้
พร้อม `google.script.run` จำลอง แล้ว `tools/t_ui.js` ขับด้วยเบราว์เซอร์จริง
ตั้งแต่วางข้อความจากไลน์จนพิมพ์ใบปะหน้าออกมาเป็นรูป

ข้อมูลในไฟล์ทดสอบทั้งหมดเป็นข้อมูลสมมติ **ห้ามเอาชื่อ เบอร์ หรือที่อยู่ลูกค้าจริง
มาใส่ในไฟล์ทดสอบ** — `tools/build.py` มีด่านตรวจเบอร์โทรไว้ให้แล้ว

## รับของเข้าสต๊อก (แท็บ 📥 รับของ)

การรับของต้องลงสองชีทเสมอ — `รับเข้า` (ยอดสต๊อก) กับ `ล็อตสินค้า` (ของให้ FEFO ตัด)
ขาดอันใดอันหนึ่งคือพังแบบเงียบ ๆ:

| ลงแค่ | ผลที่ได้ |
|---|---|
| ล็อตอย่างเดียว | ล็อตมีของ แต่ยอดคงเหลือเป็นศูนย์ · ช่องตรวจในชีทล็อตฟ้อง |
| รับเข้าอย่างเดียว | สต๊อกเพิ่ม แต่ขายไม่ได้ เพราะ FEFO ไม่มีล็อตให้ตัด |

`receiveStock()` จึงเขียนทั้งสองแถวในคำสั่งเดียว จำนวนมาจากตัวเลขเดียวกัน ล้มกลางทาง
ถอยกลับทั้งคู่ · `clientKey` กันกดซ้ำ · สินค้าที่มีล็อตอยู่แล้วจะ**ไม่ยอมให้รับเข้าโดยไม่ใส่เลขล็อต**
· เลขล็อตซ้ำของ SKU เดิมไม่ผ่าน · ยอดที่โชว์กลับมาอ่านจากชีทหลังคำนวณจริง ไม่ได้บวกเอาในแอป

## ลูกค้าเปลี่ยนใจขอส่งด่วน (ในหน้าใบปะหน้า)

กด 🖨 แล้วในหน้าต่างใบปะหน้ามีช่อง **ขนส่ง** ให้เปลี่ยนได้เลย
เปลี่ยนแล้ว **บันทึกลงชีทให้ด้วย** ไม่ใช่เปลี่ยนแค่บนกระดาษ — ไม่งั้นข้อความ
แจ้งเลขพัสดุที่ส่งลูกค้าจะให้ลิงก์ติดตามของขนส่งเจ้าเดิม

เปลี่ยนเจ้าเมื่อไร จะถามด้วยว่าจะ**ล้างเลขพัสดุเดิม**ไหม (ติ๊กไว้ให้แล้ว)
เพราะเลขของเจ้าเดิมสแกนกับเจ้าใหม่ไม่ผ่าน และลูกค้าเอาไปเช็คก็ไม่เจอ

บันทึกลงชีทไม่สำเร็จ (เน็ตสะดุด) **ยังได้ใบปะหน้าออกมาใช้** พร้อมข้อความแดง
บอกว่าต้องไปแก้ช่องขนส่งในชีทเอง — ของต้องส่งวันนี้ ระบบไม่ควรขวางงานหน้าร้าน

## หน่วยสินค้าที่เป็นตัวเลข — `qtyUnit()`

ในใบเอกสาร จำนวนกับหน่วยเขียนติดกันในช่องเดียว (ใบจริงไม่มีคอลัมน์หน่วยแยก)
ถ้าหน่วยขึ้นต้นด้วยตัวเลข ลูกค้าจะอ่านรวมเป็นเลขเดียว

ของจริงในใบเสนอราคา `QO26-00006`: สินค้า 1 ชุดที่หน่วยในฐานสินค้ากรอกไว้ว่า `10`
พิมพ์ออกมาเป็น **“1 10”** ซึ่งอ่านได้ว่า **หนึ่งร้อยสิบ** — ต่างกันสิบเท่าและเป็นเรื่องเงิน

`qtyUnit(qty, unit)` (อยู่ใน `Index.html` ใช้ได้ทุกไฟล์) จัดการให้:

| หน่วยในฐานสินค้า | พิมพ์ออกมา | ทำไม |
|---|---|---|
| `10` | `1` | ตัวเลขล้วนไม่ใช่หน่วย — คนกรอกใส่ขนาดบรรจุมา ขนาดบรรจุอยู่ในชื่อสินค้าอยู่แล้ว |
| `10pcs` | `1 (10pcs)` | ขึ้นต้นด้วยตัวเลข ใส่วงเล็บคั่นให้เห็นว่าคนละตัวเลข |
| `ชิ้น` · `ขวด` | `3 ชิ้น` | หน่วยปกติ เขียนเหมือนเดิมทุกอย่าง |

ใช้ทั้งในใบเอกสาร ข้อความที่ส่งลูกค้า และกล่องเตือนของใกล้หมด

**ทางแก้ที่ดีกว่าคือแก้ที่ต้นทาง** — ใส่หน่วยเป็นคำในชีท `ฐานสินค้า` เช่น `ชุด`
แล้วใบจะขึ้นว่า `1 ชุด` ซึ่งอ่านชัดกว่า `1` เฉย ๆ

## ลูกค้าคืนของ / ของตีกลับ (ปุ่ม ↩️ ที่แถวออเดอร์)

**ยกเลิก กับ ตีกลับ ไม่ใช่เรื่องเดียวกัน** และนี่คือเหตุผลที่แยกเป็นคนละปุ่ม

| | หมายความว่า | ต้นทุนที่เสียไปจริง |
|---|---|---|
| **✖ ยกเลิก** | ยังไม่ได้ส่ง ลูกค้าเปลี่ยนใจก่อนแพ็ค | ไม่เสียอะไร |
| **↩️ ตีกลับ** | ส่งไปแล้วแต่ของเดินทางกลับมา | **ค่าส่งสองเที่ยว** + ของอาจบุบ |

ผลต่อสต๊อกเหมือนกันเป๊ะ (ของกลับเข้าล็อตเดิม) แต่ถ้ากดยกเลิกแทนตีกลับ
สิ้นเดือนจะไม่มีทางรู้ว่าเสียค่าส่งฟรีไปกี่ใบ เพราะอะไร

และออเดอร์ที่นำเข้าเก็บ `Shopee <หมายเลข>` ไว้ในหมายเหตุ จึงเจอว่าเป็นใบ AST เลขไหน

กด **↩️** → ใส่จำนวนที่**กลับมาถึงร้านแล้วจริง**ทีละบรรทัด → บอกเหตุผล → บันทึก

- **คืนบางส่วน** → ยอดของใบเหลือเท่าที่ลูกค้าเก็บไว้ · สถานะเดิมไม่เปลี่ยน ·
  หมายเหตุขึ้น `[ตีกลับบางส่วน: SKU x2 — เหตุผล ...]`
- **คืนครบทุกชิ้น** → สถานะเป็น **ตีกลับ** · ยอดเป็น ฿0 · หัวบิลยังอยู่ในชีท
- **ค่าจัดส่งถูกล้างทุกกรณี** เพราะของไม่ได้อยู่กับลูกค้าแล้ว

### ทำไมไม่เขียนธุรกรรมขึ้นใหม่

`returnOrder()` ไม่ได้รื้อชีทเอง — คืนครบทุกชิ้นเดินทางเดียวกับ `cancelOrder`
(เพิ่มพารามิเตอร์ `kind` ให้เปลี่ยนแค่คำที่เขียนลงชีทกับ Log) ส่วนคืนบางส่วน
เดินทางเดียวกับ `editOrderItems` ทั้งสองทางถอยกลับได้ทั้งก้อนอยู่แล้วและมีข้อสอบคุมอยู่
เขียนใหม่คือเพิ่มโอกาสทิ้งออเดอร์ครึ่งใบไว้ในชีทโดยไม่ได้อะไรกลับมา

### สถานะ "ตีกลับ" ในชีท

`setupStatusList_` เติมค่านี้ให้ในชีท `ตั้งค่า` คอลัมน์ G ตอนสั่ง `setup`
ชีทที่ยังไม่ได้สั่ง setup ใหม่จะตกลงมาใช้ `ยกเลิก` แทน (ผลต่อสต๊อกเหมือนกัน)
ส่วนคำว่าตีกลับยังอยู่ในหมายเหตุกับ Log ให้ย้อนอ่านได้เหมือนเดิม

ทั้ง `ยกเลิก` และ `ตีกลับ` ถือว่า **ไม่นับเป็นยอดขาย** เหมือนกันทุกหน้า —
สรุปยอด · ปิดยอดวัน · ค้างชำระ · และไม่มีปุ่มอะไรให้กดต่อในลิสต์ออเดอร์

## ปิดยอดวัน (แท็บ 📅) — แยกหน้าจากสรุปยอด

สองหน้านี้ตอบคนละคำถาม จึงแยกกัน:

| | ตอบว่า | ข้อมูลมาจาก |
|---|---|---|
| **ปิดยอดวัน** | *วันนั้นขายไปเท่าไร* | ถามชีทด้วยวันที่ตรง ๆ (`getDayReport`) |
| **สรุปยอด** | *ช่วงนี้เป็นยังไง* — ขนส่ง ช่องทาง สินค้าขายดี | ออเดอร์ล่าสุด 500 ใบที่โหลดมา |

เหตุผลที่ **ปิดยอดวันไม่ใช้ข้อมูลชุดเดียวกับสรุปยอด**: ชุดนั้นคือใบล่าสุด 500 ใบ
พอออเดอร์สะสมมากขึ้น วันที่อยากย้อนไปปิดยอดจะหลุดออกจากชุดเงียบ ๆ
แล้วยอดของวันนั้นขาดหายไปโดยไม่มีอะไรเตือน — หน้านี้จึงกรองด้วยวันที่ตั้งแต่ในชีท
ย้อนไปไกลแค่ไหนก็ได้ครบทุกใบเสมอ

หน้าจอมี:

- **◀ ▶** เดินทีละวัน · แตะช่องวันที่เพื่อเลือกวันย้อนหลัง · ปุ่ม **วันนี้ / เมื่อวาน**
  (เดินไปวันข้างหน้าไม่ได้ ปุ่ม ▶ จะดับ)
- **ยอดขายรวม · เก็บเงินแล้ว · ยังไม่เก็บ · กำไรขั้นต้น · ค่าจัดส่ง · จำนวนชิ้น**
  นับว่าเก็บเงินได้เฉพาะใบที่สถานะ **ชำระแล้ว** — กติกาเดียวกับหน้าค้างชำระ
  ตัวเลขสองหน้าจึงตรงกันเสมอ ไม่มีทางเถียงกันเอง
- **ใบที่ยกเลิกไม่นับเข้ายอด** แต่ยังบอกว่าวันนั้นมีกี่ใบที่ยกเลิก และขึ้นในลิสต์แบบขีดฆ่า
- **ปุ่มคัดลอกสรุปวันเป็นข้อความ** สำหรับวางส่งเข้าไลน์กลุ่ม
  ข้อความคิดจากตัวเลขชุดเดียวกับที่เห็นบนจอ (`dayTotals()`) จึงไม่มีทางไม่ตรงกัน
- **แถบ 7 วันย้อนหลัง** กดแท่งไหนก็เด้งไปปิดยอดวันนั้นทันที

คำตอบของวันเก่าที่มาช้ากว่าจะถูกทิ้ง ไม่ทับวันที่กำลังดูอยู่ (กด ◀ รัว ๆ แล้วตัวเลขไม่สลับ)

## ส่งบัญชี (ปุ่ม 🧾 ที่แถวออเดอร์)

**สถานะบัญชีแยกจากสถานะออเดอร์** เพราะของถึงมือลูกค้าแล้วแต่ยังไม่ได้ส่งบัญชี
เกิดขึ้นทุกวัน ใช้ช่องเดียวกันคือเห็นได้ทีละเรื่อง แล้วใบที่ตกหล่นจะรู้อีกที
ตอนสิ้นเดือน — ซึ่งสายไปแล้วสำหรับการยื่นภาษี

`setup()` เพิ่มสามคอลัมน์ท้าย `ออเดอร์_หัวบิล` ให้: **V** สถานะบัญชี ·
**W** วันที่ส่งบัญชี · **X** ส่งบัญชีอะไรไปบ้าง
ตัวเลือกสถานะอยู่ในชีท `ตั้งค่า` คอลัมน์ **I** (เพิ่ม/แก้เองได้ ไม่ต้องแก้โค้ด):
ยังไม่ส่งบัญชี · รอเอกสาร · พร้อมส่งบัญชี · ส่งบัญชีแล้ว · บัญชีตีกลับ

**กดส่งแล้วเกิดอะไรขึ้น** — ไฟล์ลงโฟลเดอร์ไดรฟ์ `AST_ส่งบัญชี/<ปี-เดือน>/`
แล้วชีทจดว่าส่งอะไรไปเมื่อไร บัญชีเปิดโฟลเดอร์ดูเองได้ตลอด ไม่ต้องรออีเมล

| ส่งอะไรได้ | มาจากไหน |
|---|---|
| ใบกำกับภาษี / ใบเสร็จ · บิลเงินสด · ใบเสนอราคา · ใบรับเงินมัดจำ | ชีท `เอกสาร` — ติ๊กเลือกทีละใบ |
| ข้อมูลลูกค้า / เลขผู้เสียภาษี | ชีท `เอกสาร` (ใบล่าสุดที่ไม่ถูกยกเลิก) |
| เลขออเดอร์ · ช่องทางขาย · ยอดสุทธิ · ยอด VAT | ชีท `ออเดอร์_หัวบิล` |

สองอย่างท้ายรวมเป็นไฟล์ `สรุป-<เลขออเดอร์>.txt` ใบเดียว

**ไม่แนบสลิปโอนเงิน** — ร้านรับเงินผ่านธนาคารและบัญชีตรวจจากรายการเดินบัญชีเอง
ไฟล์สรุปเขียนบอกไว้ให้แล้ว ถ้าวันหนึ่งต้องแนบจริงค่อยเพิ่ม

**สิ่งที่กันไว้ให้แล้ว**

| เรื่อง | ทำอะไร |
|---|---|
| เขียนไฟล์ไม่ครบ | เก็บกวาดไฟล์ที่เพิ่งเขียนแล้ว **ไม่จดในชีทว่าส่งแล้ว**<br>สถานะที่โกหกแปลว่าไม่มีใครรู้ว่าบัญชีไม่ได้ของ จนถึงสิ้นเดือน |
| กดซ้ำ / เน็ตหลุดแล้วกดใหม่ | `clientKey` — ไม่ได้ไฟล์ชุดที่สอง |
| ใบที่ยกเลิกแล้ว | ไม่เอาไปส่งบัญชี |
| แปลงเป็น PDF ไม่ได้ | ลงเป็นรูปแทน แล้วบอกบนหน้าจอว่าไฟล์ไหนเป็นรูป ไม่ใช่ล้มทั้งการส่ง |
| ใบยังไม่เคยออกเอกสาร | บอกให้ไปออกเอกสารก่อน ไม่โชว์ช่องติ๊กเปล่า ๆ |

รูปที่ส่งเป็น **สำเนา** (ต้นฉบับเป็นของลูกค้า) วาดจาก canvas ตัวเดียวกับที่ใช้พิมพ์
จึงเป็นใบหน้าตาเดียวกับที่ลูกค้าถืออยู่ ย่อเป็น JPEG 150 dpi ก่อนส่งขึ้นไป
เพราะ PNG 300 dpi หลายใบพร้อมกันทำให้คำขอใหญ่เกินจนหลุดกลางทางแบบไม่มีข้อความบอก

⚠️ **ต้องอนุญาตสิทธิ์ไดรฟ์เพิ่มหนึ่งครั้ง** — ของเดิมแอปขอแค่สิทธิ์ชีท
พอมีการเขียนไฟล์ลงไดรฟ์ Google จะขึ้นหน้าขออนุญาตใหม่ตอนเปิดแอปครั้งแรกหลังอัปเดต
กด "อนุญาต" ครั้งเดียวจบ

## นำเข้าออเดอร์จาก Shopee (ปุ่มในแท็บ **ออเดอร์**)

ไม่ได้ทำเป็นแท็บของตัวเอง เพราะงานนี้ทำวันละครั้ง และเข้าจากแท็บ **ออเดอร์**
ซึ่งเป็นที่ที่จะไปดูผลอยู่แล้วหลังนำเข้าเสร็จ

1. Seller Centre → **คำสั่งซื้อของฉัน** → **ส่งออก** แล้วเปิดไฟล์ด้วย Excel หรือ Google ชีต
2. `Ctrl+A` แล้ว `Ctrl+C` (ต้องคลุมแถวหัวตารางมาด้วย)
3. ในแอปกดแท็บ **ออเดอร์** → **📦 นำเข้าออเดอร์จาก Shopee** → วาง → **อ่านข้อมูล**
4. หน้าจอกางให้ตรวจทีละใบก่อน แล้วค่อยกด **นำเข้า N ใบ ลงชีท**

ทำไมเป็น "วางข้อความ" ไม่ใช่ "อัปโหลดไฟล์": ไฟล์จาก Seller Centre เป็น `.xlsx`
ซึ่งแกะเองในเบราว์เซอร์ไม่ได้ ถ้าจะแกะต้องลากไลบรารีจากเน็ตเข้ามา = แอปพังทันที
ที่ลิงก์ตายหรือเน็ตร้านช้า ส่วนการก๊อปทั้งแผ่นให้ข้อมูลครบเท่ากันโดยไม่พึ่งของนอกเลย

**เอาอะไรเข้ามาบ้าง** (เจ้าของร้านกำหนดเอง 8 ก.ย. 69)

งานเดียวที่ต้องการจากออเดอร์ Shopee คือ **ตัดสต๊อกกับรู้กำไร** ที่เหลือ Shopee
ทำเองหมดตั้งแต่ใบปะหน้าจนถึงเก็บค่าส่ง ดึงเข้ามาก็ไม่มีใครใช้ต่อ แถมหน้าตรวจรก
จนดูของที่ต้องดูจริงไม่ทัน

| เอาเข้า | ไม่เอาเข้า |
|---|---|
| ชื่อลูกค้า | ที่อยู่ · เบอร์โทร |
| สินค้า · จำนวน · ราคาขาย | เลขพัสดุ · ขนส่ง |
| สถานะ (ส่งสำเร็จ / ตีกลับ) | ค่าจัดส่ง · ส่วนลดของ Shopee |
| วันจัดส่ง · หมายเลขคำสั่งซื้อ | |

**ต้นทุนกับกำไรไม่ได้มาจากไฟล์** ชีทคำนวณเองจาก `ฐานสินค้า` เหมือนออเดอร์ที่คีย์มือ
หน้าตรวจโชว์ ยอดขาย · ต้นทุน · กำไร ให้ดูก่อนกดนำเข้า

**ใบที่ตีกลับ / ยกเลิก ระบบไม่นำเข้าให้** — ของยังอยู่ที่ร้าน ถ้านำเข้าไประบบจะตัดสต๊อก
ให้ทันที กลายเป็นของหายจากชีททั้งที่ยังอยู่บนชั้น แล้วไม่มีใครรู้จนกว่าจะตรวจนับ
(ดูจากทั้งช่อง `สถานะการสั่งซื้อ` และ `สถานะการยกเลิก/คืนเงิน` และเช็คคำว่า
"ไม่สำเร็จ" ก่อน "สำเร็จ" เสมอ เพราะคำหลังเป็นส่วนหนึ่งของคำแรก)

**ใบที่ Shopee บอกว่าส่งสำเร็จแล้ว ลงชีทเป็น "ส่งแล้ว" ให้เลย** ไม่ต้องมาไล่แก้สถานะทีหลัง

**สิ่งที่กันไว้ให้แล้ว**

| เรื่อง | ทำอะไร |
|---|---|
| กันนำเข้าซ้ำ | `clientKey = sp-<หมายเลข Shopee>` และเก็บ `Shopee <หมายเลข>` ไว้ในหมายเหตุ<br>วางไฟล์เดิมซ้ำจะขึ้นว่า "นำเข้าไปแล้วเป็นใบ AST-26-00xx" แล้วข้ามให้ |
| จับคู่สินค้าไม่ได้ | บอกชื่อสินค้าที่จับไม่ได้ตรง ๆ แล้วข้ามทั้งใบ **ไม่เดาให้** |
| จับคู่ได้แต่ชื่อไม่ตรงเป๊ะ | โชว์ทั้งชื่อในชีทและชื่อบน Shopee คู่กัน จับผิดตัวจะได้เห็นก่อนกด |
| สินค้าที่ยังไม่มีต้นทุน | บอกว่า "คิดกำไรไม่ได้" ไม่ใช่นับต้นทุนเป็นศูนย์แล้วโชว์กำไรเต็มยอดขาย |
| อ่านตารางไม่ได้ | บอกชื่อคอลัมน์ที่หาไม่เจอ **พร้อมรายชื่อหัวคอลัมน์ที่อ่านได้จริง** |
| ข้อมูลใบซ้ำทุกบรรทัด | ค่าระดับใบเก็บค่าแรกที่ไม่ว่าง ไม่บวกสะสมตามจำนวนบรรทัด |

**ช่องขนส่งเว้นว่างได้แล้ว** — ของเดิมถ้าไม่ระบุขนส่ง ฝั่งชีทจะเติมตัวแรกในรายการให้เอง
(กลายเป็น Flash Express ทุกใบ) ซึ่งเป็นข้อมูลที่ไม่จริงและทำให้ใบปะหน้าบอกขนส่งผิด
ตอนนี้ไม่ระบุ = เว้นว่างไว้จริง ๆ · `setup()` ยังเติม **Shopee Xpress (SPX)** กับ
**J&T Express** ให้ในชีท `ตั้งค่า` และขยายช่วง dropdown ให้ครอบของใหม่แล้ว

การบันทึกจริงยังใช้ `createOrder()` ตัวเดิมทุกใบ — ตัดล็อต FEFO · ถอยกลับตอนล้ม ·
ตรวจยอดกับชีท เหมือนคีย์เอง ของใหม่มีแค่ "อ่านตาราง" กับ "จับคู่สินค้า" เท่านั้น

**ต้องมีในชีทก่อน** ช่องทางขายชื่อ `Shopee` ในชีท `ตั้งค่า` (มีอยู่แล้ว)
ถ้าไม่มี หน้าจอจะขึ้นเตือนสีแดงตั้งแต่ยังไม่เริ่ม ไม่ปล่อยให้กดแล้วค่อยล้มทีละใบ

ออเดอร์ Shopee บันทึกเป็น **ไม่รับ VAT** เสมอ เพราะใบกำกับภาษีออกผ่านแพลตฟอร์ม
ใบไหนต้องออกจากระบบนี้จริง ค่อยแก้ทีละใบในชีท

## ชีทขึ้น #N/A / #REF! — ตรวจด้วย `checkSheets` ก่อน

สั่งฟังก์ชัน **`checkSheets`** ใน Apps Script (อ่านอย่างเดียว ไม่แก้อะไรเลย) แล้วดูใน
**บันทึกการดำเนินการ** จะบอกว่าชีทไหนมีกี่ช่องที่ขึ้น error · ช่องแรก ๆ อยู่ตรงไหน ·
และสูตรในช่องนั้นเขียนว่าอะไร

```
✗ ล็อตสินค้า — 1005 แถว × 13 คอลัมน์ — เจอ 29 ช่องที่ขึ้น error
     I3 = #REF!   สูตร: =SUMPRODUCT(--(COUNTIF($B$6:$B$1005,'สต๊อกคงเหลือ'!$B$6:$B$150)…
     H6 = #N/A    สูตร: =IF($L6="","",SUMIFS('ตัดล็อต'!$F$6:$F$3005,…
```

ส่วนใหญ่แก้ได้ด้วยการ **สั่ง `setup` อีกครั้ง** — `setup` เขียนสูตรของทุกคอลัมน์ใหม่หมด
และขยายชีทให้สูงพอก่อนเสมอ สั่งซ้ำได้ไม่เสียหาย ไม่ลบข้อมูล

### สาเหตุที่แท้จริง — ชื่อแท็บในสูตร ต้องเป็นชื่อจริง

`findSheet_` หาแท็บ **แบบไม่ถือสา** — ช่องว่างหัวท้าย อักขระความกว้างศูนย์ และการสะกด
ต่างเล็กน้อย (`สต๊อกคงเหลือ` / `สต๊อคคงเหลือ` · `ตัดล็อต` / `ตัดล๊อต`) ถือเป็นชีทเดียวกัน
ตั้งใจให้เป็นแบบนั้น เพราะเคยพิมพ์ชื่อเพี้ยนไปตัวเดียวแล้วทั้งร้านคีย์ออเดอร์ไม่ได้ทั้งวัน

**แต่สูตรในชีทถือสาเป๊ะทุกตัวอักษร** พอเอาชื่อที่เขียนไว้ในโค้ดไปใส่ในสูตรตรง ๆ
สูตรจะชี้ไปแท็บที่ไม่มีอยู่จริง → `#REF!` ทั้งช่อง **ทั้งที่โปรแกรมอ่านเขียนชีทนั้นได้ปกติดี**
จึงดูไม่ออกเลยว่าพังเพราะอะไร

`sheetRef_(ss, name)` แก้ที่ต้นเหตุ — คืนชื่อ **แท็บจริง** พร้อมใส่เครื่องหมายคำพูดให้ถูก
(ชื่อที่มี `'` จะถูกคูณสอง) ใช้กับทุกสูตรที่อ้างข้ามชีท และ `checkSheets` จะเตือนว่า
`⚠ ชื่อแท็บจริงคือ "…"` เมื่อไม่ตรงกับชื่อในโค้ด

### ทำไม `ตัดออกแล้ว` ถึงขึ้น `#N/A` — `SUMIFS` เจ้าระเบียบเกินไป

`SUMIFS` บังคับว่าช่วงเงื่อนไขกับช่วงที่บวก **ต้องสูงเท่ากันเป๊ะ** ถ้าชีทปลายทางถูกหั่นแถว
หรือขาดคอลัมน์จนสองช่วงไม่เท่ากัน มันขึ้น `#N/A` **ทั้งคอลัมน์**

เปลี่ยนเป็น `SUMIF` แล้ว — `SUMIF` ยึดมุมซ้ายบนของช่วงที่บวก แล้วนับตามขนาดของช่วงเงื่อนไข
จึงไม่พังเพราะเรื่องนี้ (ผลลัพธ์เหมือนเดิมทุกประการ)

และช่อง **ตรวจสอบ** จะขึ้นคำว่า `สูตรช่องตัดออกแล้วเสีย — สั่ง setup ใหม่` แทนที่จะปล่อย
`#N/A` ลอยอยู่เฉย ๆ ให้ไม่มีใครสังเกต

### แอปจะไม่บอกว่า "ของไม่พอ" ทั้งที่ของเต็มชั้น

แถวล็อตที่มีทั้ง SKU และเลขล็อต ช่อง **คงเหลือ** ต้องเป็นตัวเลขเสมอ ว่างหรือขึ้น error
แปลว่า **สูตรพัง** ไม่ใช่ **ของหมด** — สองอย่างนี้แก้คนละทาง (ของหมดคือไปสั่งของ ·
สูตรพังคือของอยู่ครบแต่ระบบมองไม่เห็น)

ก่อนหน้านี้ค่าที่อ่านไม่ได้จะกลายเป็น 0 เงียบ ๆ แล้วหน้าจอบอกว่า *"ล็อตมีของไม่พอ"*
ซึ่งทำให้คนไปนั่งหาของที่ไม่ได้หาย ตอนนี้ `createOrder` จะหยุดพร้อมข้อความว่า
ช่องคงเหลือแถวไหนไม่มีตัวเลข และให้สั่ง `checkSheets` → `setup`

### ทำไมถึงพัง — สูตรอ้างเลยขอบชีทปลายทาง

สูตรที่อ้างช่วงในชีทอื่นเลยจำนวนแถวจริงของชีทนั้นไปแม้แถวเดียว Google จะให้ **ทั้งช่อง**
เป็น `#REF!` แล้วช่องที่อ้างต่อจากช่องนั้นพังตามไปทั้งแถบ

ของจริงที่เจอ: ชีท `ล็อตสินค้า` คอลัมน์ **ตัดออกแล้ว** ขึ้น error ทุกแถว ทำให้คอลัมน์
**คงเหลือ** ว่างหมด ซึ่งแปลว่า **ระบบตัดล็อต FEFO ใช้งานไม่ได้ทั้งชีท** — ของหมดอายุ
ก็ไม่รู้ว่าล็อตไหนเหลือเท่าไร

แก้ที่ต้นเหตุแล้วด้วย `boundLast_()` — ทุกสูตรที่อ้างข้ามชีทจะถูกหนีบไม่ให้เกินจำนวนแถว
จริงของชีทปลายทาง และ `setup` สร้างชีท `ตัดล็อต` ให้ครบก่อนที่ `ล็อตสินค้า` จะอ้างถึง

## สูตรในชีทพัง — ซ่อมด้วย `repairOrderSheets`

ที่ Apps Script เลือกฟังก์ชัน **`repairOrderSheets`** แล้วกด **เรียกใช้** ซ่อมได้สองอาการ

| อาการ | หน้าตา |
|---|---|
| **เลขนิ่ง** | ช่องสูตรถูกพิมพ์ทับ หรือถูก "วางเฉพาะค่า" — ตัวเลขเท่ากันทุกแถว |
| **`#REF!`** | ยังเป็นสูตร แต่ชี้ไปหาช่องที่ถูกลบ — แอปจะขึ้นป้ายแดง "ช่องสูตรเสียในชีท" |

ตัวซ่อม**ไม่เดาสูตรเอง** — คัดลอกจากแถวที่สูตรยังครบในชีทเดียวกัน (สูตรพวกนี้เจ้าของร้าน
เขียนเอง เดาผิดแม้ช่องเดียวคือใบเสร็จยอดผิด) ถ้าไม่มีแถวไหนดีเลยจะบอกให้ซ่อมมือ ไม่มั่ว
และแตะเฉพาะคอลัมน์ใน `CALC` เท่านั้น ช่องที่คนกรอกเองไม่ถูกแตะ

ถ้ามีเลขนิ่งค้างอยู่**ใต้**แถวสุดท้ายที่มีสูตร จะรายงานเลขแถวให้ไปกด Delete เอง —
ไม่ลบให้เพราะแยกไม่ออกว่าตั้งใจเขียนไว้เองหรือเปล่า

### ถ้าไม่เหลือแถวดีให้เป็นต้นแบบเลย — `writeVatFormulas`

เกิดขึ้นได้เมื่อสูตร `#REF!` ถูกคัดลอกไปทับทั้งคอลัมน์ `repairOrderSheets` จะบอกว่า
"ไม่มีแถวไหนสูตรครบเลย" ตอนนั้นให้สั่ง **`writeVatFormulas`** ซึ่งเขียนสูตรสองช่องนี้
ที่ `ออเดอร์_หัวบิล` คืนให้:

```
M (VAT)          = (ยอดสินค้า − ส่วนลด + ค่าจัดส่ง) × ตั้งค่า!B8   เฉพาะใบที่ "รับ VAT"
N (ยอดชำระสุทธิ)  = ยอดสินค้า − ส่วนลด + ค่าจัดส่ง + VAT
```

**ค่าส่งอยู่ในฐานภาษีด้วย** — เคยเข้าใจผิดมาก่อนแล้วเกือบทำพัง ตัวเลขเก่าในชีทคิด VAT จาก
ยอดสินค้าอย่างเดียว แต่ใบเสร็จที่ลูกค้าถืออยู่คิดรวมค่าส่งมาตลอด (ONIV26-00246 ฐาน 1,350
VAT 94.50 · 00247 20.09 · 00252 18.35 · 00255 238.63 · 00259 134.75) **ชีทต่างหากที่เพี้ยน
จากใบจริง** ยึดใบที่ออกไปแล้วเป็นหลักเสมอ และตรงกับที่ `buildDoc_()` คิดตอนออกเอกสารด้วย

**นี่เป็นที่เดียวในระบบที่ยอมเขียนสูตรของเจ้าของร้านเอง** อัตรา VAT อ่านจาก `ตั้งค่า!B8`
ซึ่งเป็นช่องเดียวกับที่ `cfgGet_()` ใช้ ไม่ฝัง 7% ไว้ในสูตร

ถ้าสูตรยังดีอยู่มันจะไม่ยอมเขียนทับ ต้องยืนยันด้วย `writeVatFormulas('เขียนทับ')` ·
แตะแค่สองคอลัมน์นี้ ในช่วงแถวที่มีสูตรอยู่แล้ว · ลงบันทึกในชีท `Log` ทุกครั้ง

> **7 ก.ย. 69** ช่อง VAT กับยอดสุทธิของใบที่ "รับ VAT" เป็น `#REF!` ทั้งคอลัมน์
> ตัวซ่อมรุ่นเดิมดูแค่ว่าขึ้นต้นด้วย `=` ไหม เลยนับว่าปกติและไม่ซ่อมให้

## สำรองไฟล์ชีทอัตโนมัติ (`Backup.gs`)

6 ก.ย. 69 ไฟล์ชีทถูกลบโดยไม่ตั้งใจ กู้จากถังขยะไม่ทัน รอดมาได้เพราะบังเอิญมีแท็บ
ที่เปิดค้างไว้ให้ก๊อปข้อมูลออกมา — ครั้งหน้าอาจไม่มีแท็บนั้น

**ต้องวางใน Apps Script โปรเจกต์ใหม่ ไม่ใช่โปรเจกต์ของแอปคีย์ออเดอร์** เพราะการก๊อป
ไฟล์ต้องขอสิทธิ์เข้าถึง Google Drive ถ้าใส่รวมไปในแอป พนักงานทุกคนที่เปิดแอปจะโดน
ถามสิทธิ์ Drive ตามไปด้วยทั้งที่ไม่ได้ใช้ ให้เจ้าของร้านคนเดียวอนุญาตในโปรเจกต์นี้พอ

1. https://script.google.com → **โปรเจกต์ใหม่** ตั้งชื่อ `AST สำรองชีทอัตโนมัติ`
2. วาง `Backup.gs` ทั้งไฟล์ทับโค้ดตัวอย่าง → 💾 บันทึก
3. เลือกฟังก์ชัน `setupBackup` → **เรียกใช้** → อนุญาตสิทธิ์ Drive ครั้งเดียว
4. เสร็จ — จะได้โฟลเดอร์ `AST_สำรองชีทอัตโนมัติ` พร้อมไฟล์สำรองใบแรกทันที

| ฟังก์ชัน | ทำอะไร |
|---|---|
| `setupBackup()` | ตั้งให้สำรองเองทุกวันตอนตีหนึ่ง + สำรองให้เลยหนึ่งรอบ · กดซ้ำไม่เกิดทริกเกอร์ซ้ำ |
| `backupStatus()` | สำรองล่าสุดเมื่อไร มีกี่ไฟล์ ล้มครั้งสุดท้ายเพราะอะไร |
| `backupNow()` | สำรองเดี๋ยวนี้หนึ่งรอบ |
| `stopBackup()` | เลิกสำรองอัตโนมัติ (ไฟล์ที่สำรองไว้แล้วไม่ถูกลบ) |

ของเก่ากว่า 30 วันจะถูก**ย้ายลงถังขยะ** ไม่ใช่ลบถาวร และ**เหลือไว้อย่างน้อย 7 ไฟล์เสมอ**
ต่อให้เก่าหมดทุกใบ · ไฟล์ที่ชื่อไม่ตรงรูปแบบ `AST สำรอง YYYY-MM-DD HHMM` จะไม่ถูกแตะ
ถึงจะอยู่ในโฟลเดอร์เดียวกัน · ก๊อปล้มเมื่อไร จะไม่ไปลบของเก่าทิ้ง

ย้ายไฟล์ชีทเมื่อไร ต้องมาตั้ง `SHEET_ID` ที่คุณสมบัติสคริปต์ของโปรเจกต์นี้ด้วย
ไม่งั้นจะสำรองไฟล์เก่าต่อไปเรื่อย ๆ

## สิ่งที่ระบบกันไว้ให้แล้ว

- คนสองคนกดพร้อมกัน → `LockService` กันเลขออเดอร์ซ้ำ
- กดซ้ำ / เน็ตหลุดแล้วยิงใหม่ → `clientKey` ทำให้ได้ออเดอร์ใบเดิม ไม่ใช่ใบใหม่
- บันทึกล้มกลางทาง → ล้างแถวที่เพิ่งเขียนออกหมด ไม่ทิ้งออเดอร์ครึ่งใบ (และไม่ล้างสูตรทิ้ง)
- ยอดที่ชีทคำนวณไม่ตรงกับที่ควรเป็น → ยกเลิกทั้งใบ ดีกว่าปล่อยยอดผิดค้างไว้
- ชีทเต็ม (สูตรลากมาไม่ถึง) → บอกตรง ๆ ว่าเต็มและสูตรมีถึงแถวไหน
- ล็อตไม่พอ / ล็อตหมดอายุ → ไม่ตัดขาย บอกตัวเลขจริงว่าเหลือเท่าไร
