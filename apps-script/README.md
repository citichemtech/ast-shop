# หลังบ้าน — Apps Script บนชีทของร้าน

โค้ดในโฟลเดอร์นี้ทำงานอยู่บน Google ไม่ใช่ในเครื่อง ข้อมูลทั้งหมดอยู่ในชีท
`AST_ระบบออเดอร์และสต๊อก3008` ไม่มีข้อมูลลูกค้าอยู่ในไฟล์เหล่านี้เลย

## กติกาข้อเดียวที่ห้ามลืม

ชีทของร้าน **ใส่สูตรรอไว้ทุกแถวแล้ว** ตั้งแต่แถว 6 ถึงแถว 501 (หัวบิล) และ 1201 (รายการ)
แถวที่ดูว่างเปล่าก็มีสูตรอยู่ มันแค่คืนค่าว่างเพราะยังไม่มีข้อมูลให้คำนวณ

> เขียนตัวเลขทับช่องสูตรเมื่อไร สูตรแถวนั้นหายถาวร
> ยอดสินค้า ต้นทุน กำไร VAT ของออเดอร์ใบนั้นจะค้างเป็นเลขนิ่ง ไม่อัปเดตอีกเลย และไม่มีอะไรฟ้อง

`Sheets.gs` จึงมีตาราง `SH` บอกว่าคอลัมน์ไหนกรอกได้ คอลัมน์ไหนเป็นสูตร
และ `writeRow_()` จะโยน error ทันทีถ้ามีโค้ดพยายามเขียนลงช่องสูตร

| ชีท | ช่องที่เขียนได้ | ช่องสูตร ห้ามแตะ |
|---|---|---|
| ออเดอร์_หัวบิล | A–I, K, L, Q, S, T | J, M, N, O, P, R, U |
| ออเดอร์_รายการ | B, D, G, I | A, C, E, F, H, J–P และ Q ที่เพิ่มใหม่ |

## ไฟล์

| ไฟล์ | ทำอะไร |
|---|---|
| `Sheets.gs` | รู้ว่าคอลัมน์ไหนอยู่ตรงไหน · อ่าน/เขียนแถวอย่างปลอดภัย · หาแถวว่าง |
| `Fefo.gs` | เลือกล็อตที่หมดอายุก่อนมาตัดก่อน — โค้ดล้วน ไม่แตะชีท ทดสอบด้วย node ได้ |
| `Shopee.gs` | อ่านไฟล์ออเดอร์ที่ export จาก Shopee — โค้ดล้วน ไม่แตะชีท ทดสอบด้วย node ได้ |
| `Setup.gs` | สร้างชีท `ล็อตสินค้า` · `ตัดล็อต` · `จับคู่SKU` · `นำเข้า Shopee` และเพิ่มคอลัมน์ Q ที่ `ออเดอร์_รายการ` |
| `Api.gs` | สิทธิ์เข้าใช้ · เสิร์ฟหน้าเว็บ · `createOrder()` บันทึกออเดอร์ |
| `Stock.gs` | หน้าสต๊อก · จับคู่ SKU · ตรวจก่อนตัด · ตัดสต๊อกจาก Shopee · คืนสินค้า · ประวัติ |
| `ShopeeApi.gs` | ช่องเชื่อม Shopee Open API — เตรียมไว้ ยังไม่เปิดใช้ |
| `Index.html` | หน้าจอคีย์ออเดอร์บนมือถือ |
| `Stock.html` | หน้าจอสต๊อก · นำเข้า Shopee · จับคู่ SKU · ประวัติ |

## ติดตั้งครั้งแรก

1. เปิดชีท → เมนู **ส่วนขยาย › Apps Script**
2. เพิ่มไฟล์ตามรายการข้างบน (ไฟล์ `.gs` เลือกชนิด **สคริปต์** · `.html` เลือก **HTML**
   ตอนตั้งชื่อไม่ต้องพิมพ์นามสกุลต่อท้าย)
3. **การตั้งค่าโปรเจกต์** → ติ๊ก "แสดงไฟล์ appsscript.json" แล้ววางเนื้อหาจาก `appsscript.json` ทับ
4. เลือกฟังก์ชัน **`setup`** กด **Run** ครั้งเดียว แล้วอนุญาตสิทธิ์ตามที่ Google ถาม
   (สั่งซ้ำได้ ไม่ทำข้อมูลหาย · จะซ่อมสูตร `#REF!` ในชีทสต๊อกให้ด้วยถ้ามี)
5. **ทำให้ใช้งานได้ › การทำให้ใช้งานได้ใหม่ › เว็บแอป**
   - ทำงานในชื่อ: **ผู้ใช้ที่เข้าถึงเว็บแอป**
   - ผู้ที่มีสิทธิ์เข้าถึง: **ทุกคนที่มีบัญชี Google**
6. ส่งลิงก์ที่ได้ให้พนักงาน — เปิดจากมือถือแล้วกด "เพิ่มลงหน้าจอโฮม" ได้เลย

## ใครเข้าระบบได้

**แชร์ชีทให้ใคร คนนั้นใช้แอปได้** — ไม่ต้องตั้งอะไรเพิ่ม ไม่ต้องรู้ว่าโดเมนบริษัท
เป็น Google Workspace หรือเปล่า

> เปิดชีท → กด **แชร์** → ใส่อีเมลพนักงาน → เลือก **ผู้แก้ไข**

เหตุผลที่ผูกกับการแชร์ชีท: คนที่แก้ชีทได้ ก็ทำทุกอย่างที่แอปทำได้อยู่แล้ว
การมีรายชื่อสองที่ให้ดูแลมีแต่จะหลุด

ด่านนี้ไม่ได้อ่านรายชื่อผู้แก้ไขมาเทียบ แต่**ลองเปิดชีทในนามคนที่กดเข้ามาตรง ๆ**
เปิดได้คือผ่าน เพราะแอปทำได้แค่เท่าที่บัญชีนั้นทำกับชีทได้อยู่แล้ว และการเขียน
ยังมี Google กันอีกชั้น คนที่มีสิทธิ์แค่ดูจะบันทึกออเดอร์ไม่ผ่านอยู่ดี

> เคยทำแบบอ่านรายชื่อจาก Drive มาก่อนแล้วพัง — แอปทำงาน "ในชื่อผู้ใช้ที่เข้าถึง"
> DriveApp จึงถามในนามพนักงาน ซึ่งคนที่เป็นแค่ผู้แก้ไขมักอ่านรายชื่อผู้ร่วมงานไม่ได้
> ได้รายชื่อว่างกลับมา แล้วปฏิเสธคนที่เจ้าของแชร์ชีทให้เรียบร้อยแล้วจริง ๆ

พอเปิดผ่านแล้วระบบจำไว้ 5 นาที ส่วนคำว่า "ไม่ผ่าน" ไม่ถูกจำ — แชร์ชีทเสร็จเข้าได้ทันที
เอาคนออกก็ถอนสิทธิ์ในชีทตามปกติ (รออีกไม่เกิน 5 นาที)

ยังมีอีกสองทางสำรองที่ผ่านได้เหมือนกัน ใช้เมื่อจำเป็น:

| ทาง | ตั้งที่ไหน |
|---|---|
| อีเมลลงท้าย `@chem-inno-tech.com` | ค่า `ALLOW_DOMAIN` ใน `Api.gs` |
| รายชื่อเฉพาะราย | การตั้งค่าโปรเจกต์ › คุณสมบัติของสคริปต์ คีย์ `ALLOW_EMAILS` |

ด่านจริงอยู่ใน `requireStaff_()` ไม่ใช่ที่หน้าจอ — คนที่ไม่ผ่านทั้งสามทาง
ต่อให้รู้ลิงก์ก็เรียกฟังก์ชันไม่ได้ และถ้าระบบอ่านอีเมลไม่ออก จะปฏิเสธไว้ก่อนเสมอ

## ทดสอบก่อนแตะของจริง

```bash
node tools/t_fefo_unit.js                          # ตรรกะ FEFO
node tools/t_shopee_unit.js                        # ตัวอ่านไฟล์ Shopee
node tools/t_order_sheet.js                        # บันทึกออเดอร์บนชีทจำลอง
node tools/t_shopee_sheet.js                       # นำเข้า Shopee · คืนสินค้า บนชีทจำลอง
python3 tools/make_preview.py
node tools/t_ui.js                                 # หน้าคีย์ออเดอร์ในเบราว์เซอร์จริง
node tools/t_ui_stock.js                           # หน้าสต๊อก/นำเข้า Shopee ในเบราว์เซอร์จริง
```

`tools/fakesheet.js` จำลอง SpreadsheetApp มากพอที่จะรัน `Sheets.gs` กับ `Api.gs`
ได้ทั้งไฟล์ และ **จดไว้ทุกครั้งที่มีการเขียนทับช่องสูตร** — ข้อสอบที่สำคัญที่สุด
ของชุดทดสอบนี้คือรายการนั้นต้องว่างเปล่า

`tools/make_preview.py` ประกอบไฟล์ทั้งหมดเป็นหน้าเว็บไฟล์เดียวที่เปิดในเครื่องได้
พร้อม `google.script.run` จำลอง แล้ว `tools/t_ui.js` ขับด้วยเบราว์เซอร์จริง
ตั้งแต่วางข้อความจากไลน์จนพิมพ์ใบปะหน้าออกมาเป็นรูป

ข้อมูลในไฟล์ทดสอบทั้งหมดเป็นข้อมูลสมมติ **ห้ามเอาชื่อ เบอร์ หรือที่อยู่ลูกค้าจริง
มาใส่ในไฟล์ทดสอบ** — `tools/build.py` มีด่านตรวจเบอร์โทรไว้ให้แล้ว

## สิ่งที่ระบบกันไว้ให้แล้ว

- คนสองคนกดพร้อมกัน → `LockService` กันเลขออเดอร์ซ้ำ
- กดซ้ำ / เน็ตหลุดแล้วยิงใหม่ → `clientKey` ทำให้ได้ออเดอร์ใบเดิม ไม่ใช่ใบใหม่
- บันทึกล้มกลางทาง → ล้างแถวที่เพิ่งเขียนออกหมด ไม่ทิ้งออเดอร์ครึ่งใบ (และไม่ล้างสูตรทิ้ง)
- ยอดที่ชีทคำนวณไม่ตรงกับที่ควรเป็น → ยกเลิกทั้งใบ ดีกว่าปล่อยยอดผิดค้างไว้
- ชีทเต็ม (สูตรลากมาไม่ถึง) → บอกตรง ๆ ว่าเต็มและสูตรมีถึงแถวไหน
- ล็อตไม่พอ / ล็อตหมดอายุ → ไม่ตัดขาย บอกตัวเลขจริงว่าเหลือเท่าไร

## นำเข้าออเดอร์ Shopee แล้วตัดสต๊อก

Shopee ไม่ได้เปิด API ให้ร้านทั่วไปใช้ฟรี ระบบจึงรับ**ไฟล์ที่ export จาก Seller Centre**
(คำสั่งซื้อของฉัน → ส่งออก) ได้ทั้ง `.xlsx` และ `.csv` หรือจะก๊อปทั้งตารางจาก Excel มาวางก็ได้

ลำดับงานในแอป: **แท็บสต๊อก → นำเข้า Shopee**

1. เลือกไฟล์ ระบบอ่านหัวตารางเอง (รองรับทั้งไฟล์ไทยและอังกฤษ) ถ้าจับคอลัมน์ผิด
   กด "ตรวจการจับคอลัมน์" แล้วเลือกเองได้ — Shopee เปลี่ยนชื่อคอลัมน์มาแล้วหลายรอบ
2. ตั้งว่าจะตัดสต๊อกให้ออเดอร์สถานะไหน (ค่าตั้งต้น: ที่ต้องจัดส่ง · จัดส่งแล้ว · สำเร็จ)
3. กด **ตรวจก่อนตัดสต๊อก** — ขั้นนี้**ไม่เขียนอะไรลงชีทเลยสักช่อง** บอกว่าใบไหนตัดได้
   ใบไหนติดอะไร และจะตัดล็อตไหนไปเท่าไร
4. กด **ตัดสต๊อก** ระบบบันทึกเป็นออเดอร์ในชีทตามปกติ ผ่านทางเดียวกับการคีย์ด้วยมือทุกประการ

### สามเรื่องที่ต้องรู้ก่อนใช้

**หนึ่ง — ชีทออเดอร์มีเพดานแถว** `ออเดอร์_หัวบิล` มีสูตรถึงแถว 501 (ราว 495 ใบ)
และ `ออเดอร์_รายการ` ถึงแถว 1201 (ราว 1,195 บรรทัด) ยอด Shopee วันละหลายสิบใบ
ทำให้ชีทเต็มได้ในไม่กี่สัปดาห์ หน้าสต๊อกกับหน้าตรวจจึงโชว์ที่ว่างที่เหลือไว้ตลอด
และระบบจะ**ปฏิเสธการตัด**ทันทีเมื่อที่ว่างไม่พอ ไม่เขียนครึ่ง ๆ ทิ้งไว้
พอใกล้เต็มต้องลากสูตรของสองชีทนั้นลงเพิ่มเอง (เป็นชีทของเจ้าของร้าน สคริปต์ไม่แตะให้)

**สอง — กำไรที่ชีทคำนวณจะสูงกว่าความจริง** ถ้าเลือก "บันทึกยอดขายเต็ม"
เพราะชีทไม่รู้จักค่าคอมมิชชั่นและค่าบริการที่ Shopee หักไป (ปกติราว 10–15%)
เลือก "หักเป็นส่วนลด" แล้วยอดสุทธิจะใกล้เงินที่ได้รับจริง แต่ฐานภาษีของใบนั้นจะลดลงตามไปด้วย
**ให้ตกลงกับฝ่ายบัญชีก่อนว่าจะเอาแบบไหน** ไม่ว่าเลือกแบบไหน ค่าธรรมเนียมเต็มจำนวน
ถูกเก็บไว้ที่ชีท `นำเข้า Shopee` เสมอ

**สาม — ตัดซ้ำคือความผิดพลาดที่แพงที่สุด** ชีท `นำเข้า Shopee` เก็บเลขที่คำสั่งซื้อทุกใบ
ที่นำเข้าไปแล้ว นำเข้าไฟล์ที่ช่วงวันซ้อนกันได้ไม่ต้องกลัว **ห้ามลบแถวในชีทนั้นทิ้ง**
ลบเมื่อไรระบบจะตัดใบเดิมซ้ำโดยไม่มีอะไรเตือน

### กำไรที่เห็นในระบบ ครอบคลุมแค่ไหน

ชีทคิดกำไรจาก **ราคาขาย − ต้นทุนในชีท ฐานสินค้า** เท่านั้น สำหรับออเดอร์ Shopee
แปลว่ามีของที่มันยังไม่รู้จัก

| หัก/ไม่หัก | รายการ |
|---|---|
| ✅ หักให้ | ต้นทุนสินค้า (จากชีท `ฐานสินค้า` คอลัมน์ G) |
| ✅ หักให้ | ส่วนลดที่ร้านออกเอง — ไฟล์ Shopee ส่ง "ยอดขายสินค้า" มาแบบหักแล้ว |
| ⚠️ เลือกได้ | ค่าคอมมิชชั่น + ค่าบริการ Shopee (โหมด "หักเป็นส่วนลด") |
| ❌ ไม่หัก | ค่าโฆษณา Shopee Ads — ไม่มีในไฟล์ออเดอร์เลย |
| ❌ ไม่หัก | ค่าส่งส่วนที่ร้านสมทบ |

**ต้นทุนต้องครบก่อน ไม่งั้นตัวเลขกำไรไม่มีความหมาย** — SKU ที่ช่องต้นทุนว่างหรือเป็น 0
ชีทจะคิดกำไรเท่ากับราคาขายทั้งก้อน หน้าตรวจก่อนตัดจึงขึ้นเตือนไว้ให้ว่า
ใบที่กำลังจะตัดมีสินค้าตัวไหนยังไม่ใส่ต้นทุนบ้าง — เตือนเท่านั้น ไม่ห้ามตัด
เพราะเรื่องบัญชีไม่ควรไปหยุดงานคลัง

ต้นทุนในชีทเป็นสูตรทั้งเส้น ใส่ย้อนหลังได้ทุกเมื่อ **ยอดกำไรของออเดอร์เก่าจะคำนวณใหม่ให้เองทั้งหมด**
ไม่ต้องนำเข้าซ้ำ

### จับคู่ SKU

ไฟล์ที่ Shopee ส่งออกมาไม่มี SKU ของร้านอยู่เลย ชีท `จับคู่SKU` คือที่ที่บอกระบบว่าอะไรคืออะไร
ใส่**รหัส** (ที่ตั้งไว้ในหน้าสินค้าของ Shopee) ไว้ก่อนเสมอ — ชื่อสินค้าบน Shopee เปลี่ยนบ่อย
พอเปลี่ยนแล้วการจับคู่ด้วยชื่อจะหลุดทันที

สินค้าจัดเซต เช่น Shopee ขายเป็นแพ็ค 5 ให้ใส่ `5` ที่ช่องตัวคูณ ระบบจะตัดสต๊อก 5 ชิ้น
ต่อ 1 แพ็คที่ขายได้ และหารราคาต่อชิ้นกลับให้ ยอดขายในชีทจึงเท่ากับที่ Shopee เก็บลูกค้าจริง

รายการที่ยังจับคู่ไม่ได้ **ระบบจะกันทั้งใบไว้ ไม่ตัดสต๊อกให้** เพราะเดา SKU ผิดคือตัดของผิดตัว
แล้วรู้ตัวอีกทีตอนของขาด · กดปุ่ม "ไปจับคู่รายการเหล่านี้" จากหน้าตรวจได้เลย

### คืนสินค้า

ปุ่ม ↩ ที่แท็บออเดอร์ ของจะกลับเข้าล็อตเดิมที่ตัดไป (แถวจำนวนติดลบในชีท `ตัดล็อต`)
และลงชีท `รับเข้า` เป็นรายการของคืน **แถวออเดอร์เดิมไม่ถูกลบ** — การขายเกิดขึ้นจริง
และอาจออกเอกสารไปแล้ว ที่เปลี่ยนคือของกลับเข้าคลัง ไม่ใช่การขายนั้นไม่เคยเกิด

## ช่องเชื่อม Shopee API

`ShopeeApi.gs` เตรียมไว้แล้วแต่ยังไม่เปิดใช้ ตัวตรวจและตัวตัดสต๊อกรับ "ออเดอร์รูปมาตรฐาน"
เท่านั้น ไม่รู้เลยว่าออเดอร์มาจากไฟล์หรือจาก API วันเปลี่ยนมาใช้ API จึงไม่ต้องแตะ
ตรรกะการตัดสต๊อกซึ่งเป็นส่วนที่พังแล้วเจ็บที่สุด

วันที่จะเปิดใช้จริง:

1. ใส่ค่า 4 ตัวที่ **การตั้งค่าโปรเจกต์ › คุณสมบัติของสคริปต์**
   `SHOPEE_PARTNER_ID` · `SHOPEE_PARTNER_KEY` · `SHOPEE_SHOP_ID` · `SHOPEE_ACCESS_TOKEN`
2. เพิ่ม scope `https://www.googleapis.com/auth/script.external_request` ใน `appsscript.json`
   (ยังไม่ใส่ไว้ เพราะจะทำให้พนักงานทุกคนต้องกดอนุญาตสิทธิ์ใหม่ทั้งที่ยังไม่ได้ใช้)
3. รัน `shopeeApiSelfTest()` แล้วทดสอบกับร้านจริง

> โค้ดส่วนที่ยิงหา Shopee **ยังไม่เคยทดสอบกับ API ของจริง** เพราะไม่มีบัญชี Open Platform
> ให้ทดสอบ ห้ามเชื่อว่าใช้ได้จนกว่าจะได้ลองกับร้านจริง · กดปุ่ม "สถานะช่องเชื่อม Shopee API"
> ในแอปดูได้ตลอดว่าตอนนี้ขาดค่าอะไร
